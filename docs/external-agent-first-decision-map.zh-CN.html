AGPair V1External Agent First
决策点 运行流 执行器 落地顺序 验收

给人看的改造地图 / 不是给 AI 执行的长计划

让 Codex 少干体力活，外部 Agent先上。

这次改造的核心不是“多接几个 CLI”，而是重新规定责任边界： Codex 做主控和验收，AGPair 调度外部执行器，失败再换人或重试。

01外部 agent 是默认劳动力，Codex 子 agent 只做 fallback。
02授权在派发时给预算，越界就结构化 blocked，然后开新 attempt retry。
03只认 CLI：Antigravity CLI、Grok CLI、Claude Code、Codex CLI；Gemini 新任务退场。
1 个主控 Codex main 负责拆任务、派发、整合、最终验证。
4 个 executor antigravity-cli / grok-cli / claude-code / codex。
0 个 IDE bridge Antigravity 不再指 IDE 或桌面端，只指 CLI。
2 条禁线 不做运行中审批状态机；不做复杂 capability profile。

七个决策点

看完这里就能判断后续代码改造有没有跑偏。每张卡都是一个实现时必须保持的边界。

责任边界

Codex 不是劳动力池

Codex main 只保留最关键的判断工作：理解意图、拆 brief、派发、验收 diff/test。

要外部 agent 先执行
不要默认开 Codex 子 agent
项目入口

`target` 不是白名单

任何 git repo 都应该能派发。`target` 只保存少数项目的默认配置，不是“允许派发的项目列表”。

要自动识别 git root
不要要求先 target list
命名清理

Antigravity 只指 CLI

`antigravity` 容易混进 IDE/桌面端/bridge。新 canonical id 用 `antigravity-cli`。

要shell 调 CLI
不要IDE extension bridge
执行器名单

Gemini 新任务退场

Gemini CLI 已被 Antigravity CLI 取代。历史 receipt 可读，但新 start/retry 不再使用 Gemini。

要保留历史可 inspect
不要新任务路由到 Gemini
权限模型

派发时授权，越界就停

executor 没有人帮它点 approve。V1 给授权预算，超出预算写结构化 blocked。

要dispatch-time profile
不要运行中模拟审批
重试语义

retry 是新 attempt

不强求原进程从中断行恢复。retry 自动带上原 brief、blocked 原因、log tail、git 状态和新授权。

要state-aware retry
不要复杂 resume 协议
调度策略

薄 routing table 就够了

现在不做完整 capability profile。先用一张小表记录优先级、默认授权、适合/不适合任务。

要可调整的静态表
不要动态评分系统

一次任务怎么跑

V1 的精髓是终态 blocked + 新 attempt retry。看起来不如原进程 resume 优雅，但更稳、更可审计。

new Codex 写 brief 目标、scope、非目标、验证命令、授权 profile。
acked AGPair 派 CLI 优先外部 executor，默认 antigravity-cli。
working 范围内执行 本地编辑、测试、提交，只能在授权预算内。
terminal 提交或 blocked 成功写 COMMITTED；越界写 BLOCKED。
retry 新 attempt 接手 Codex 读上下文，扩授权或换 executor。

V1：现在要做

new
任务创建，brief 和授权预算已确定。
acked
executor 已启动，AGPair 可 wait/watch。
committed
有结构化 receipt、diff、验证命令；Codex 再复验。
blocked
终态。用 `retry --from-block` 新开 attempt。
stuck
运行失败或无进展，优先换外部 executor。

V2：以后再说

`acked -> approval_required -> acked/resumed` 暂时不做。它要求所有 CLI 都支持暂停、声明请求、等待审批、恢复。这个抽象现在太脆。

defer
不建 approval request 表。
defer
不做 CAS 状态转换和过期审批。
defer
不模拟各家 CLI 的确认机制。

执行器怎么分工

不是谁最聪明就先用谁，而是“便宜外部资源先消耗，质量不够再升级”。

优先级 Executor 默认用途 默认授权 边界
10 antigravity-cli 实现、修测试、常规重构、长任务。 local_mutating 默认第一执行器；只走 CLI，不走 IDE/桌面端。
20 grok-cli 探索、第二意见、便宜重试、失败后换脑子。 local_readonly 起步 能力先用 smoke/benchmark 校准，不预设它一定擅长大改。
30 claude-code 复杂重构、代码质量、review、语义细节。 local_mutating 质量升级档；不作为最低成本默认。
90 codex 外部都不可用、不达标，或任务太贴近当前 Codex 上下文。 local_mutating fallback。Codex native subagent 也属于 fallback，不走 AGPair executor 表。

落地顺序

后续改代码按这个顺序推进，能避免先建复杂抽象、再回头拆掉。

1. 清 executor 名字

新增 `antigravity-cli / grok-cli / claude-code / codex`；Gemini 从新任务入口移除。

2. 替换 Antigravity 路径

把默认 Antigravity executor 从 bridge/agent-bus 改为 Antigravity CLI adapter。

3. 让 repo 自动识别

不传 `--repo-path` / `--target` 时，用当前目录的 git root；target 只做 profile。

4. 加授权 profile

持久化 `local_readonly / local_mutating / local_test_heavy / external_network`，并注入 prompt。

5. 做 `retry --from-block`

自动拼 original brief、blocked receipt、log tail、git status、diff、新授权和新 executor。

6. 更新 skill/docs/doctor

Codex 规则写清：外部 agent first；子 agent fallback；Codex main 永远复验。

验收时只看这些

执行完成不能只看命令成功。下面这些都满足，才算改造没有偏离决策。

✓不注册 target，也能在任意 git repo 里 `task start`。
✓新任务 executor 只显示 `antigravity-cli / grok-cli / claude-code / codex`。
✓Gemini 历史记录能看，新 start/retry 不能用。
✓Antigravity 默认路径不再经过 IDE bridge。
✓`blocked(approval_required)` 是终态，不试图原进程恢复。
✓`retry --from-block` 自动带上足够上下文。
✓scope 外修改会进入 receipt/验收失败路径。
✓Codex 最后自己读 diff、跑验证，再声明完成。
